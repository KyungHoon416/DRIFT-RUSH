**핵심 확정:** Unity 금지, iOS+Android, Godot 4.7.2 Stable, GDScript, 3D, 자동 가속, 스마트폰 기울기 조향, Firebase 백엔드, 스피드전+아이템전, 친구 2~8명.

## 0. 에이전트 역할과 완료 기준

당신은 시니어 Godot/GDScript 엔지니어, 3D 테크니컬 아티스트, 실시간 멀티플레이 엔지니어, 모바일 빌드 엔지니어, Firebase 보안 엔지니어, QA 리드다.

**요구하는 산출물은 이미지나 웹 시뮬레이터가 아니라, 실제 Godot 프로젝트다.** `project.godot`, 실행 가능한 `.tscn` 씬, `.gd` 스크립트, 3D 리소스, 테스트, 설정, README, 로그 및 빌드 보고서를 작성한다. Work/Claude가 파일을 실제로 만들 수 있는 환경이라면 생성·실행·검증까지 수행한다. 단순 기획·목업으로 완료했다고 말하지 않는다.

참고 이미지:
- `DRIFT_RUSH_UI_CONCEPT.png`: 로비 / 맵 선택 / 친구 대기실 / 인게임 HUD의 아트 방향, 정보 구조 참고
- `DRIFT_RUSH_RACE_REFERENCE.png`: 밝은 벚꽃 레이싱 트랙, 오렌지 카트, 3인칭 추적 카메라, 아이템전 분위기 참고

두 PNG는 **레퍼런스 이미지**다. 이를 화면 전체에 붙여서 레이싱하는 척하지 않는다. 실제 트랙 Mesh, 차량 Mesh, CollisionShape3D, Camera3D, UI Control 노드를 만들어 작동시킨다. 이미지를 픽셀 단위로 복제할 필요는 없고, 아트 스타일·색채·HUD 위계와 사용자 경험을 가능한 비슷하게 구현한다. 타인의 기존 레이싱 게임의 명칭, 캐릭터, 맵, 모델, 소스 등을 무단 복제하지 않는다.

## 1. 기술 스택 고정

- **게임 엔진:** Godot **4.7.2 Stable**, 표준 빌드, GDScript (C#/.NET 사용하지 않음)
- **렌더러:** 모바일용 Renderer 우선, 저사양 기기 Compatibility 대체 옵션 검토
- **3D 아트:** Blender 또는 Godot에서 직접 생성한 메쉬, 합법적으로 사용 가능한 CC0/상업적 이용 허용 에셋
- **모바일:** Android APK/AAB, iOS Godot Xcode Export 프로젝트
- **로그인·데이터:** Firebase Authentication, Cloud Firestore, Realtime Database(Presence), Cloud Functions, Crashlytics/Analytics(지원 연동 상태에 따라 단계 적용)
- **실시간 레이스:** Godot high-level multiplayer + ENet, 장기적으로 권한 있는 전용 게임 서버
- **금지:** Unity, WebView 기반 레이싱, HTML/Three.js만으로 전체 게임 대체, Flutter/React Native를 3D 주행 엔진으로 사용

**Firebase 주의:** Firebase의 Unity SDK를 Godot에 가져다 붙이지 않는다. Godot를 공식 지원하는 SDK가 있다고 가정하지 않는다. 우선 `FirebaseAdapter` 계층을 만들고, 지원되는 Firebase Auth REST/HTTPS 및 Cloud Functions API 또는 유지보수/라이선스/플랫폼 호환성이 확인된 Godot용 플러그인을 선택한다. 플러그인이 불안정하면 REST 연동으로 대체한다. Firebase 서비스 계정의 개인 키·서버 비밀은 앱에 포함하지 않는다.

**실시간 네트워크 주의:** Firestore/Realtime Database에 차량의 위치를 프레임마다 기록하지 않는다. Firebase는 계정/친구/설정/전적/초대 코드용, ENet 게임 서버는 차량 상태·입력·충돌·아이템/랩 판정용. 전용 UDP 게임 서버는 Cloud Functions/Cloud Run 일반 HTTP 서비스와 동일하게 생각하지 않는다. 운영 배포 시 적합한 VM/UDP 게임 서버 호스팅을 검토한다.

## 2. 실무 진행 규칙

1. 환경 조사: 현재 OS, Godot 실행 가능 여부 및 버전, Android SDK, Xcode, Git, Blender, Firebase 인증 상태를 확인하라.
2. 사용 가능한 로컬 또는 Work 클라우드 컴퓨터에서 실제 프로젝트를 생성하라. 도구 미지원/권한 거부 시 해당 장애를 명시하고 **독립적으로 실행 가능한 프로젝트 소스**를 우선 전달하라.
3. 구체적인 단계별 결과를 테스트하라. `Godot 설치 불가`, `Android SDK 없음`, `Xcode(macOS) 없음`, `Firebase 인증 없음` 등의 상황에서 실행한 척하지 마라.
4. 유료 에셋 구매, Firebase 유료 플랜 활성화, 클라우드 서버 지출, 스토어 제출 등 비용/외부 변경이 발생하는 행동은 명시적으로 사용자에게 승인받아라. 무료·로컬 대안으로 먼저 진행하라.
5. 기존 저장소가 있으면 구조를 파악하고 보존하라. 신규 저장소라면 `DRIFT_RUSH_GODOT/`에 생성하라.
6. 비밀키나 사용자의 Apple 계정/Keystore 비밀번호를 저장소/보고서에 기록하지 마라.
7. 각 단계 끝에 변경 파일, 실행 결과, 남은 이슈를 `Docs/PROGRESS.md`에 기록한다.
8. 질문 없이 가능한 사항은 합리적 기본값으로 진행하되, 배포 계정, 지출, 기존 데이터 삭제는 사용자 결정으로 남긴다.

## 3. 게임 룰 / 조작 (확정)

- 카메라: 기본 가로 화면 16:9, 후방 3인칭 추적, 코너에서 자연스러운 스무딩
- 가속: 출발 신호 이후 항상 자동 가속, 최고속도와 가속도는 데이터 파일로 조정
- 조향: 스마트폰의 중력/가속도 및 필요 시 자이로 정보를 이용해 **기기를 좌우로 기울이면 좌우 회전**
- 보정: 조작 튜토리얼에서 현재 기기 자세를 중립으로 캘리브레이션. 앱 재실행/화면회전/일시정지 복귀에도 안전하게 처리
- 민감도: 기본 1.0, 범위 예 0.5~2.0; 데드존/스무딩/조향 방향 반전 옵션
- 조향 대체: 에디터/PC에서 A/D 및 화살표, 모바일에서는 터치 좌우 버튼(센서 없는 기기 포함)
- 드리프트: 우측 DRIFT 버튼을 누른 상태 + 일정 조향각/속도 조건, 미끄러짐/드리프트 게이지/바퀴 연출
- 부스터: 게이지 충전 후 BOOST 버튼, 타이머, 트레일 파티클, 사운드, 효과 종료
- 브레이크: 좌측 BRAKE 버튼을 누를 때 감속; 버튼 해제 후 자동 가속 재개
- 충돌: 벽/카트/아이템 타격은 서로 다른 감속·임팩트 연출, 사운드와 기기 진동
- 물리: 랩/체크포인트 통과, 역주행 알림, 트랙 밖 이탈 시 안전 위치 복구
- 경기 기본값: 3 LAP, 2~8명, 개인전, 팀전은 후속 확장
- 스피드전: 드리프트+부스터로 승부, 공격 아이템 없음
- 아이템전: 맵의 아이템 상자, 미사일/실드/터보/방해 아이템 등; 조작·공정성·쿨다운 규칙 분리

**센서 테스트 필수:** `Input.get_gravity()`/`Input.get_accelerometer()` 등 실제 Godot 4.7 API를 공식 문서/에디터에서 확인하라. 센서 입력은 PC 편집기에서 값이 0일 수 있으니 데스크톱 키보드 대체가 반드시 작동해야 한다. 축 방향은 기기 방향/설정마다 다를 수 있으므로 실기기에서 검증·보정한다.

**진동 테스트 필수:** `Input.vibrate_handheld(duration_ms, amplitude)` 지원 범위를 검사하고 Android VIBRATE 권한 및 플랫폼별 대체 처리를 검증한다. iOS에서 더 섬세한 패턴이 필요하면 네이티브 플러그인 경유, 사용자가 진동을 끄면 모든 촉각 피드백 비활성화. 충돌 반복 시 쿨다운 200~400ms(제안값), 작은 충돌은 과장하지 않는다. 진동 호출을 네트워크에 직접 송신하지 않는다. 각 클라이언트가 유효 충돌 이벤트를 받아 로컬에서 실행한다.

## 4. 필요한 UI / UX 화면과 동작

모든 UI는 Godot Control/Container 기반, 가로 Safe Area 및 다양한 종횡비 대응. 터치 타깃을 충분히 크게 하고 주요 버튼은 항상 한 손/두 손 조작이 편하도록 배치한다.

### G-01 시작 / 로그인
- 로고, 게스트로 시작, 이후 Apple/Google 연결(기기별 가능 여부 확인)
- 자동 로그인/세션 복원/오프라인 연습 모드
- 실패 시 재시도와 분리된 오류 메시지

### G-02 메인 로비
- 중심에 회전 가능한 3D 카트와 캐릭터, 닉네임/레벨(레벨은 후속), START 버튼
- 친구, 차고, 설정, 랭킹, 모드 선택 진입
- 최초 구현은 진짜 3D 차고와 카트, 버튼으로 연결된 로비

### G-03 모드 선택
- 스피드전, 아이템전, 연습하기 탭
- 각 모드 상세 규칙과 선택 상태, 친구방 만들기/참가 진입
- 아이템전 미구현 단계에서 해당 모드를 완성된 것처럼 노출하지 말고 `개발 중` 처리

### G-04 방 만들기 / 참가
- 방 공개/비공개, 정원(2~8), 모드, 맵, 랩 수, 6자리 초대 코드(예시), 복사/공유
- 존재하지 않는 코드, 이미 시작한 경기, 방 인원 가득 참 예외

### G-05 친구 대기실
- 최대 8명 카드, 준비됨/미준비/연결 끊김, 방장 배지
- 방장은 맵/모드 변경과 경기 시작(2명 이상 + 참가자 전원 준비)
- 다른 플레이어는 준비/취소, 방장 퇴장 처리, 중복 입장 방지

### G-06 맵 선택
- 'Sakura Valley' / 'Neon City' 2개의 미리보기, 난도, 곡률, 트랙 길이(설계값)
- 첫 배포는 Sakura Valley 1개 완성, 두 번째는 구조/플레이 가능 상태로 확장
- 선택 시 방 데이터/로컬 연습에 반영

### G-07 카트 선택 / 차고
- 3D 카트 360도 뷰, 색상 선택, 기본 카트 1종 + 외형 프리셋
- 유료 부품/승률에 영향을 주는 강화 시스템은 MVP 제외

### G-08 기울기 튜토리얼
- 스마트폰 좌우 기울이기 가이드, 현재 기울기 실시간 표시, 중립 보정 버튼
- 감도 설정, 반전, 터치 대체, 센서 권한/미지원 안내
- 연습 주행으로 이동

### G-09 실제 3D 레이스 HUD
- 왼쪽 상단: 대형 현재 순위(예 2/8), 펼칠 수 있는 순위표
- 상단 중앙: LAP 2/3, 경과 시간, 베스트랩
- 오른쪽 상단: 미니맵(실제 트랙 기반) + 설정
- 하단 왼쪽: BRAKE, 아이템(아이템전만)
- 하단 중앙: 현재 속도, 드리프트/부스터 게이지
- 하단 오른쪽: BOOST, 큰 DRIFT 버튼
- 경기 중 화면을 가리는 모달 금지. 화면 흔들림/입력 가림/위치 오작동을 피할 것

### G-10 일시정지 / 접속 오류
- 싱글에서는 정상 일시정지, 멀티에서는 로컬 UI만 중지하고 서버 시뮬레이션은 지속
- 계속, 음향/진동 조정, 퇴장 확인
- 재연결 진행/실패/종료 안내

### G-11 경기 결과
- 1~8위 결과, 타임, 최고랩, 플레이어 닉네임, 보상(검증된 서버 결과만)
- 재경기 준비, 같은 방으로, 로비로 나가기
- 동률 및 기권자(DNF) 정책

### G-12 설정
- 모션 감도, 데드존, 좌우 반전, 터치 조작 전환, 진동 ON/OFF 및 강도
- BGM/SFX 볼륨, 그래픽 품질(낮음/중간/높음), FPS(30/60)

### G-13 프로필 / 친구 / 랭킹
- 닉네임/프로필/친구코드, 친구 목록, 최근 경기, 스피드전 개인 기록
- 클라이언트 임의 기록 업로드 금지

UI 상세 정책은 `DRIFT_RUSH_UI_SPEC.md`를 함께 참고.

## 5. 3D 아트 디렉션 / 맵 / 카트

- 카툰/스타일라이즈드 3D. 밝은 파스텔 벚꽃, 따뜻한 햇빛, 선명한 오렌지 스포츠 카트, 네온 블루 부스터, 과장되지 않은 금속 반사.
- **실제 운전 가능한** `Sakura Valley` 트랙 1개를 우선 완성. 시작/결승선, 곡선, 가드레일, 충돌 영역, 체크포인트 최소 6개, 아이템 스폰 위치, 복구 지점.
- 트랙 배경: 벚꽃나무, 풍차, 폭포, 아치 다리, 산, 풍선. 비용 없는 프리미티브/절차적 메쉬로 시작해 시각적으로 개선할 것.
- 3D 차량: 차체 MeshInstance3D, 바퀴 4개(시각 회전), 드라이버 자리, 바퀴·부스터 이펙트, 라이트.
- 자산이 없으면 저폴리곤 메쉬를 직접 만들고, `Assets/Licenses/ASSET_ATTRIBUTION.md`에 출처/라이선스 명시. 불명확한 자산은 포함하지 마라.
- 성능 기준: 모바일 성능 측정 후 목표 60FPS, 낮은 등급에서는 30FPS 옵션. 그림자, 파티클, 폴리곤, 텍스처 크기, 드로우콜을 품질 프리셋으로 조절.

## 7. 레이싱 구현 요구

- 우선 단순하면서도 운전감이 좋은 `CharacterBody3D` 기반 아케이드 카트 구현을 고려. `RigidBody3D` 사용 시 조작감/안정성/네트워크 예측 측정 후 선택.
- 매 물리 프레임 위치 계산, 가속/감속/조향/드리프트/부스터/충돌을 분리. 기울기 입력을 물리 루프에 안정적으로 적용.
- 카트의 시각적 회전과 충돌 바디 방향, 바퀴 연출, 카메라 방향의 일관성 확보.
- 추적 카메라가 벽/지형을 뚫지 않도록 충돌 보정, 급회전 시 과도한 회전·멀미 방지.
- 플레이 가능 성능 우선. 렌더용 이미지나 단순 카메라 팬 애니메이션으로 주행을 대체하지 않는다.

## 8. 네트워크 · Firebase 백엔드 설계

**Phase A: 로컬 싱글 플레이 (반드시 먼저)**
- 서버 없이 연습 모드 진행 가능, 타임 기록·랩·HUD 동작.
- `MockBackend.gd`로 Firebase 계정 없이도 전체 로컬 흐름 확인 가능.

**Phase B: 2인 LAN 프로토타입**
- Godot ENet 이용해 2개 클라이언트에서 차량 위치·회전·랩·시작/종료 동기화.
- 상대방 차량은 보간 적용. 플레이어 탈주/재입장 기본 처리.

**Phase C: Firebase 친구방 + 2~8인 레이스**
- Firebase 익명 로그인/게스트 업그레이드, 닉네임, 친구방 코드, 설정·결과 저장.
- Cloud Functions는 서버 검증된 보상·결과 처리 API, Firestore/RTDB에는 룸 메타정보, 친구/온라인 상태만 저장.
- 경기 서버에서 레이스 규칙/아이템 충돌/체크포인트/결승 순위를 검증.
- 클라이언트는 본인 입력을 전송, 서버는 상태를 권한 있게 갱신, 클라이언트는 예측/보간/재조정.
- 서버 인증: Firebase ID token을 신뢰 가능한 백엔드에서 검증한 뒤 짧은 유효시간의 게임 접속 토큰 발급.
- 클라이언트가 보낸 `rank`, `coins`, `finish_time`을 그대로 기록하지 않는다.
- 네트워크 tick rate는 초기 측정값(예 15~30Hz), 보간·대역폭·지연·패킷 손실을 테스트해 결정. 60Hz 시각 FPS와 네트워크 tick은 별개.
- 모바일 셀룰러/와이파이 전환, 백그라운드 진입/복귀, 지연 150ms·패킷 손실 3%의 리허설을 포함.
- UDP 서버가 필요한 경우 실제 배포 대상(예: VM)을 선택하고 비용 설명. 지출 승인 전 유료 자원 생성 금지.

**Firebase 설정 전까지:** `FirebaseAdapter.gd`에 메서드 시그니처와 개발용 MockBackend를 제공하되, 실제로 연결되었다고 허위 보고하지 않는다. 사용자 비밀을 소스에 넣지 않는다. Auth/Firestore Rules 테스트와 App Check는 출시 전 보안 단계.

## 9. 구현 순서 / 단계별 완성 정의

### Milestone 0 — 환경 검사 + 저장소
- 실제 Godot 버전·headless 실행 가능 여부 확인
- README, 구조, `.gitignore`, 기본 테스트 계획

### Milestone 1 — 플레이 가능한 3D 카트 (최우선)
- 카트 1대 + SakuraValley 트랙 + 카메라 + 자동 가속 + 키보드 대체 조향

- 원근감이 있는 3D 화면, 차량 이동, 카메라 따라가기, 벽 충돌

### Milestone 2 — 모바일 조작감
- 센서 조향 / 중립 보정 / 민감도 / 터치 대체 / 드리프트 / 부스터 / 브레이크
- 기기 진동, 효과음, 레이스 HUD, 설정, 실기기 테스트
- Android APK 빌드 검증, Mac이 있으면 iOS Xcode export 및 기기 검증

### Milestone 3 — 앱 UX/3D 그래픽
- 로비, 차고, 모드 선택, 맵 선택, 튜토리얼, 일시정지, 결과
- 3D 오브젝트 스타일/조명/이펙트·최적화

### Milestone 4 — 멀티플레이·Firebase
- 2인 LAN 동기화 → Firebase 계정·방 → 최대 8인 친구방 및 서버 연동
- 서버 검증된 결과·보상, 재접속/기권, 네트워크 QA

### Milestone 5 — 아이템전 확장
- 아이템 상자/미사일/실드/부스터/함정, 밸런싱과 서버 판정
- 2번째 맵 NeonCity 및 추가 카트 외형

**중요:** 이번 작업 실행 환경에서 가능한 한 많은 단계를 진행하되, 제일 먼저 Milestone 1을 완전히 동작시키라. 시간 부족 시 부분 구현을 남기고 나머지 단계를 TODO로 공개한다. `모든 기능 완성`이라고 속이지 않는다.

## 10. 검증 및 산출물

- 파일 유효성: 모든 참조 에셋 존재, `.tscn` 파일 리소스 경로 오류 없음, 구문 오류 없음.
- Godot 실행 테스트: 환경에서 지원되는 명령(`godot --headless --path ... --editor --quit` 등)의 사용법을 `godot --help`로 검증한 뒤 실행한다.
- UI 테스트: 진입/뒤로가기/방장/준비 상태/중복 요청/Empty/Loading/Error 상태.
- 물리 테스트: 좌우 조향/중립 보정/자동 가속/벽 충돌/부스터 만료/랩 체크포인트/역주행.
- 3D 그래픽 테스트: 실제 카트 Mesh 표시, 카메라 동작, 트랙 충돌, 최소 HUD, 화면 비율.
- 모바일: Android 내보내기 APK/AAB 확인; iOS는 macOS+Xcode 사용 가능 시만 export·서명 검증.
- 센서/진동은 실제 디바이스가 없다면 `실기기 미검증`으로 명확히 표시.
- 서버 테스트: 적어도 호스트+클라이언트 2개 인스턴스, 위치 동기화·퇴장/복구·결과 처리.
- 그래픽 벤치마크: 최소 한 대의 실제 모바일 디바이스에서 FPS 기록. 실행 환경 없으면 추정 성능과 측정값 구분.
